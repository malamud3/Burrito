# Burrito

הדגמת מחקר להשוואת חקירת פונקציות בגישה קלאסית ובמסלול רנאטו סאיג — React + Vite.

> **הדגמה בלבד — לא לשימוש באיסוף נתוני מחקר.** הקצאה אקראית נשמרת בדפדפן
> מקומי ואינה מתואמת בין מכשירים. אין להשתמש בציונים או בהקצאות מהדגמה זו
> להסיק מסקנות מחקריות.

## הרצה

```bash
npm install
npm run dev      # שרת פיתוח  → http://localhost:5173
npm run build    # בנייה לפרודקשן (dist/)
npm test         # בדיקות יחידה + בדיקת זרימה מלאה
```

## מסלולי הפעילות

לאחר הבוחן המקדים, המשתתפים מקבלים אוטומטית אחד משני מסלולים לחקירת אותה פונקציה רציונלית:

* **מסלול קלאסי** — שאלות מתמטיות ישירות על תחום ההגדרה, קיצון, אסימפטוטות, חיתוכים, תחומי עלייה/ירידה וגרף.
* **מסלול רנאטו סאיג** — אותן שאלות פתוחות בחמישה שלבים, ובנוסף משימות מפורשות של פירוק, הפשטה, זיהוי תבניות ותכנון אלגוריתמי.

## רצף התוכן המחקרי

1. **בוחן מקדים משותף**, לפני הצגת המסלול: עשר אותן שאלות על פונקציה מקבילה `h(x) = x² / (x² − 8x + 15)`, ללא רמזים או כלי שרטוט.
2. **פעילות למידה** על `f(x) = x² / (x² − 4x + 3)`: אחד משני מסלולים בחמישה שלבים ובאותו סדר.
3. **בוחן העברה משותף**: אותן עשר שאלות על פונקציה חדשה `g(x) = x² / (x² − 6x + 8)`, ללא רמזים או כלי עזר.

בשני המסלולים יש אותן מטרות מתמטיות, חמישה שלבים באותו סדר, אותן שאלות פתוחות, אותם רמזים, אותו כלי שרטוט, 30 דקות ומדיניות עזרה זהה. בכל אחד מארבעת השלבים הראשונים יש גם שדה טקסט נוסף, באותו ממשק ונדרש להמשך: ברנאטו הוא מציג פעולת CT; בקלאסי הוא מבקש נימוק מתמטי מקביל. טיימר הלמידה מתחיל אחרי הגשת הבוחן המקדים; עם תום 30 דקות עוברים לבוחן ההעברה. הבוחנים אינם מוגבלים בזמן ונרשמים בנפרד. טבלת הסימנים הממולאת מראש ותבניות הקלט הייחודיות לרנאטו הוסרו.

הגרסה עדיין מיועדת להדגמה בלבד: ההקצאה אינה מתואמת בין מכשירים, והשקילות של משימות הביקורת, קושי הבוחנים וזמן הפעילות לא נבדקו בפיילוט. אין להסיק ממנה מסקנות סיבתיות או להשתמש בנתונים לאיסוף מחקרי.

הפונקציות בבוחנים תוכננו כמקבילות מבנית, אך עדיין לא עברו כיול אמפירי של שקילות הקושי; יש לבדוק זאת בפיילוט לפני הסקת מסקנות מהשוואת ציונים.

ההקצאה מתבצעת אחרי הבוחן המקדים באמצעות בלוקים אקראיים בגודל שניים, ונשמרת ב-`localStorage`. מנגנון זה מיועד להדגמת זרימת ההקצאה בדפדפן יחיד בלבד: בכל דפדפן נוצר רצף עצמאי, אין תיאום בין מכשירים, וקוד משתתף כפול מזוהה רק באותו דפדפן. לפיכך ההקצאה אינה מתאימה לניסוי רב-מכשירי או לאיסוף מחקרי.

## נתוני מחקר

* אירועי הלוג כוללים מזהה סשן, קוד משתתף, המסלול שהוקצה, שיטת ההקצאה, חותמת זמן וסוג פעולה; לוגים של משתתפים קודמים אינם נמחקים אוטומטית בעת התחלת סשן חדש.
* תשובות הבוחן המקדים, התשובות המתמטיות, משימות העיבוד ובוחן ההעברה נשמרות ומיוצאות לצד אירועי התחלה והגשה. תשובות חלקיות נשמרות.
* משך הלמידה נמדד מהגשת הבוחן המקדים עד סיום הפעילות או תום הזמן, ולא כולל את הבוחנים.
* לוח החוקר כולל מסך ניקוד ידני שמסתיר את קוד המשתתף והמסלול: 0–2 נקודות לכל אחד מעשרת סעיפי הבוחן, עד 20 נקודות. ניקוד נשמר כאירועי לוג, וייצוא JSON כולל גם את הציון העדכני לכל סשן; קובץ "ציוני בוחנים" CSV מסכם שורה לכל סשן, עם ציוני סעיפים וגרסאות מחוון.
* לוח החוקר מאפשר לייצא לוגים מצטברים בפורמטי JSON ו-CSV. קובץ ציוני הבוחנים כולל מסלול אך אינו כולל קוד משתתף. יש לייצא גיבוי לפני ניקוי נתוני הדפדפן.
* נתונים והקצאות נשמרים מקומית ואינם נשלחים לשרת; מחיקת נתוני האתר מאפסת את היסטוריית המשתתפים. זהו אב-טיפוס בלבד, לא מערכת לניהול הקצאה מחקרית.

הסתרת פרטי המשתתף במסך הניקוד אינה עיוורון מלא, כי לוח החוקר עדיין מאפשר גישה ללוגים הגולמיים. המחוון הוא עזר לניקוד עקבי ואינו מחליף הכשרת מעריכים או בדיקת מהימנות בין מעריכים. יש לבצע פיילוט לפני שימוש מחקרי; אין להסיק מסקנות סיבתיות מההדגמה.

טיוטת פרוטוקול לבדיקת בהירות, שקילות הבוחנים, מהימנות ניקוד וזמני ביצוע נמצאת ב-[docs/pilot-validation.md](./docs/pilot-validation.md).

טיוטת תכנית הניתוח לתוצא הראשי, חסרים ובדיקות נתונים נמצאת ב-[docs/analysis-plan.md](./docs/analysis-plan.md).

הניווט בין מסכי הפעילות מבוסס כתובות דרך React Router. תוכן השאלות והנתונים הצפויים של פונקציית רנאטו מוגדרים תחת `src/core/constants/`.
